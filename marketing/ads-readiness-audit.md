# Аудит готовности geoaeo.pro к контекстной и таргетированной рекламе (28.07.2026)

## Вердикт: сайт НЕ готов к запуску — есть блокирующий пробел

Технически сайт быстрый, безопасный и с сильными посадочными страницами. Но **на сайте нет ни одной системы аналитики** — ни GA4, ни Google Ads Tag, ни Meta Pixel. Проверено напрямую в исходном коде и в реальном HTML продакшена: скриптов `googletagmanager`, `gtag(`, `fbq(` — ноль, только Next.js чанки. При этом Content-Security-Policy сайта явно упоминает google-analytics.com — то есть кто-то (или прошлая версия сайта) собирался подключить аналитику, но так и не сделал этого.

**Что это значит на практике:** если запустить рекламу прямо сейчас — деньги будут потрачены, но:
- Google Ads не увидит ни одной конверсии → алгоритм Smart Bidding не сможет оптимизировать показы, будет откручивать бюджет вслепую.
- Meta не получит данных для оптимизации показа рекламы и не сможет строить аудитории ретаргетинга.
- Вы не узнаете, сколько заявок реально пришло с рекламы, а сколько органически.

Это самая частая причина, по которой первый рекламный бюджет "сгорает впустую" — и её надо закрыть до, а не после запуска.

## Блокирующие пункты (закрыть до старта рекламы)

### 1. Нет GA4 (Google Analytics 4)
Не установлен вообще. Без него нет данных о поведении посетителей, источниках трафика и (что важно) невозможно корректно импортировать конверсии в Google Ads.

### 2. Нет тега конверсий Google Ads
Даже если завтра запустить кампанию — Ads не узнает, кто из перешедших по рекламе оставил заявку.

### 3. Нет Meta Pixel (Facebook/Instagram)
Без пикселя: нет данных для оптимизации показов, нет аудитории ретаргетинга, Lead Ads будут работать хуже и дороже.

### 4. CSP заблокирует пиксели, если их просто вставить "как есть"
Технический нюанс, который легко пропустить: заголовок Content-Security-Policy сайта явно ограничивает домены, откуда разрешено грузить скрипты и на какие домены разрешено отправлять данные:
```
script-src: только 'self', googletagmanager.com, google-analytics.com
connect-src: только 'self', google-analytics.com, vercel-insights.com, supabase.co
```
Meta Pixel обращается к `connect.facebook.net` и `www.facebook.com/tr` — этих доменов в списке нет. **Если просто вставить код пикселя, браузер молча заблокирует его** (ошибка видна только в консоли разработчика — то есть вы решите, что пиксель работает, а данные никуда не будут поступать). Domain для Google Ads conversion (`googleadservices.com`) тоже придётся добавить.

### 5. Нет верификации домена в Meta Business Manager
Начиная с изменений Apple iOS14, Meta требует подтверждённый домен для надёжной атрибуции конверсий (Aggregated Event Measurement). Без этого шага данные с iPhone-пользователей будут теряться частично.

### 6. Нет событий-конверсий на форме и WhatsApp/телефоне
Форма заявки на `/contacts` показывает успех прямо на странице (без перехода на отдельный "thank-you" URL) — это нормально, но для трекинга нужно вручную прописать событие (`gtag('event', 'generate_lead')` / `fbq('track', 'Lead')`) в момент успешной отправки, а не полагаться на "визит на страницу". Аналогично не инструментированы клики по кнопке WhatsApp и номеру телефона — а это частый канал обращения в вашей нише.

## Что уже готово и работает хорошо

- **Скорость:** TTFB 0.34 с — с запасом проходит требования Quality Score в Google Ads и Meta.
- **HTTPS и заголовки безопасности:** полный набор (HSTS, CSP, X-Frame-Options и т.д.) — не будет предупреждений "небезопасно", это плюс для доверия и Quality Score.
- **Mobile viewport** настроен корректно.
- **UTM-метки не теряются** — проверено на редиректах (apex→www, trailing slash): параметры `utm_source` и т.п. проходят без потерь.
- **Посадочные страницы коммерческие и готовы принимать трафик:** `/services/geo-aeo-optimizaciya`, `/services/seo-prodvizhenie-almaty` и другие — с ценами, FAQ, разметкой Schema.org. Хорошая база для Quality Score и конверсии.
- **Политика конфиденциальности** уже содержит базовое упоминание cookies и аналитики (Google Analytics, Яндекс.Метрика указаны как пример) — минимальное юридическое прикрытие для рекламы есть, обновить формулировку нужно будет только после реального подключения пикселей.
- **Юрлицо указано** (ТОО «Агентство») — понадобится для верификации рекламных аккаунтов.

## План действий перед запуском (по порядку)

1. **Создать GA4-ресурс** (analytics.google.com) → получить Measurement ID (`G-XXXXXXX`).
2. **Создать Google Ads аккаунт** → создать конверсию (форма + клик по WhatsApp/телефону) → получить Conversion ID/Label.
3. **Создать Meta Business Manager** → Meta Pixel → получить Pixel ID → верифицировать домен geoaeo.pro (мета-тег или DNS TXT, через Namecheap — по той же схеме, что делали для Google Search Console).
4. **Прислать мне все три ID** — я:
   - обновлю CSP в `next.config.ts`, добавив нужные домены Meta и Google Ads;
   - вставлю GA4 + Google Tag через `next/script`;
   - вставлю Meta Pixel с корректной инициализацией;
   - подключу события конверсии на успешную отправку формы и на клики WhatsApp/телефон;
   - обновлю Политику конфиденциальности под реальный список используемых сервисов;
   - задеплою и проверю через Google Tag Assistant и Meta Pixel Helper, что всё реально стреляет, а не блокируется CSP.
5. Только после этого — запуск кампаний по плану из `audit-and-ads-plan.md`.

**Срок:** шаги 1–3 — ваши (займут около часа суммарно, не требуют разработки). Шаг 4 — мой, займёт 30–60 минут после получения ID.
